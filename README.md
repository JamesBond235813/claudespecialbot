# Digital Delivery Telegram Bot

一个面向通用数字服务的 Telegram 预约与次日人工交付系统。

## 已实现

- X → Telegram `start` 参数来源归因
- `/start` 直接进入商店；可选欢迎文案与商品按钮在同一条消息里
- 分类步骤可在后台开关；分类可单独隐藏和排序
- Telegram Bot 商品浏览、条款确认和订单查询
- 商品分类、库存显示与 1/2/5 件数量选择
- 下单时原子预留库存；取消/过期订单释放库存
- 0 定金直接预约
- USDT 定金/尾款的人工核验与链上交易哈希去重
- 管理后台确认到账并向客户发送状态通知
- 管理后台人工交付，正文直接发送且不写入订单日志
- 次日交付时间计算
- FastAPI 管理接口
- Vue 3.5 管理后台
- 商品、活动链接和订单状态管理
- MySQL 订单、支付、状态历史与幂等数据结构

## 本机启动

1. 复制 `.env.example` 为 `.env` 并填写数据库、Bot Token、管理密钥、USDT 网络及公共收款地址。
2. 创建数据库：`digital_delivery_bot`，字符集 `utf8mb4`。
3. 安装后端依赖并启动：

   ```bash
   python3.12 -m venv .venv
   .venv/bin/pip install -r backend/requirements-dev.txt
   .venv/bin/uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8001
   ```

4. 安装前端依赖并构建后台：

   ```bash
   cd frontend
   npm install
   npm run build
   ```

5. 打开 `http://127.0.0.1:8001/admin/`，使用 `.env` 中的 `ADMIN_API_KEY` 登录。

后端测试：

```bash
cd backend
../.venv/bin/pytest
```

## 商店设置

分类步骤、文案和条款正文保存在 `app_settings` 表，在管理后台「设置」中修改，保存后立即生效，无需重启。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| 显示分类步骤 | 开启 | 关闭后，`/start` 和 `/products` 跳过分类按钮，直接列出可见分类中的在售商品 |
| 分类显示 | 全部显示 | 隐藏某个分类后，其中商品不会出现在机器人里 |
| 欢迎文案 | 空 | 仅 `/start` 时加在商店消息顶部。留空则第一条消息就是选购按钮 |
| 商店引导文案 | 请选择需要预约的数字服务： | 分类列表或全部商品列表上方的主文案 |
| 分类内引导文案 | 请选择商品： | 进入分类后的提示 |
| 条款正文 | 空（使用内置条款） | `/terms` 的正文。版本号仍由 `TERMS_VERSION` 控制 |

`/start` 带渠道参数时仍会归因，例如 `https://t.me/ClaudeSpecialbot?start=x_default`。下单前的数量选择和「同意条款并预约」不变。

## 管理后台

登录后使用侧栏进入：概览、订单、付款核验、商品、分类、客户、来源链接、设置。订单支持搜索和状态/来源筛选，详情里可以查看状态历史、核验付款、驳回交易哈希并发送交付。商品和分类可以新建、编辑、删除（已有订单或商品时改为停用/隐藏），并设置价格、定金、库存、可见性和排序。

## Bot 命令

- `/start`：进入商店（保留渠道参数归因）
- `/products`：查看商品，遵循分类步骤开关
- `/orders`：查看最近订单
- `/txid <订单号> <交易哈希>`：提交 USDT 交易哈希
- `/terms`：服务条款
- `/support`：人工客服
- `/paysupport`：支付支持

## X 链接

在帖子中使用：

```text
https://t.me/ClaudeSpecialbot?start=x_default
```

后台可创建不同 campaign code，以区分帖子、广告或合作渠道。

## 升级已有数据库

服务启动时会自动迁移，不需要手工改订单数据：

- 创建 `categories`、`app_settings` 表
- 为 `products` 增加 `sort_order`（默认 0）
- 按现有商品的分类名回填分类，默认全部可见
- 写入默认商店设置；已有设置不会被覆盖

部署时拉取代码、重新构建前端并重启后端即可。重启后到「设置」按需关闭「显示分类步骤」。已发出的 Telegram 分类按钮若仍使用旧序号，会按原来的分类名称打开；新按钮使用分类 ID。

## 安全说明

- `.env` 已被 Git 忽略，不要提交 Token、密码或管理密钥。
- USDT 到账目前由运营人员检查交易哈希后手动确认；尚未集成链上自动监控、二维码支付或 10 分钟付款过期机制。
- 商品库存留空表示不限库存；将商品数量设为 0 会在用户端显示售罄。商品价格和定金按件计算。
- USDT 订单由后台人工核验交易哈希，不会仅凭客户提交的哈希自动标记到账。
- 管理接口通过 `X-Admin-Key` 保护。当前监听 `127.0.0.1`，对外开放前应配置 HTTPS 反向代理。
- 生产环境建议将密钥迁移到系统 Secret 管理服务。
- 管理后台的交付弹窗会把内容直接发给对应 Telegram 客户；正文不会存入订单记录或审计日志。
- 不要把私钥、助记词或交易所登录信息放进 `.env` 或订单交付内容。
